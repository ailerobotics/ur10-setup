The teach pendant's network page may say “not connected” — on a direct cable this is cosmetic: its check wants a route to the internet, which doesn't exist here by design. Judge the link by the health checklist, never by that page. Setting the pendant's gateway field to 192.168.0.2 usually silences it.

02Topology

Point-to-point ethernet. No DHCP, no gateway — the host profile is never-default so this link can never capture the machine's internet route.

03How it got here

The full sequence, including the failures — they carry most of the information.

  1. Aug 13 · 17:28
    Host network configured
    NetworkManager profile ur10 on enp5s0: static 192.168.0.2/24 + link-local fallback, ipv4.never-default yes. The stale DHCP profile was disabled so it can't race for the port.
  2. Aug 13 · 17:33
    Driver stack installed — around the Isaac apt trap
    NVIDIA's Isaac repo overrides most ros-jazzy-ur* packages with a force-win 99.2.0 version but not ur-description — an unpinned install mixes incompatible halves. Pinned the whole stack to packages.ros.org → coherent 3.8.0.
  3. Aug 13 · 17:45
    Robot identified from the wire
    Ping sweep found one host; dashboard confirmed UR10, CB3 (PolyScope 3.15.8). CB3 ⇒ headless_mode works with no URCap on the pendant.
  4. Aug 13 · 17:50
    Factory kinematics extracted
    ur10_calibration.yaml pulled from the arm; driver later verified its checksum against the robot.
  5. Aug 13 · 17:51
    Collision: two driver instances
    A second stack failed with “speed_slider_mask … controlled by another RTDE client”. Lesson encoded in the runbook: exactly one driver may run. Both were stopped; one clean instance brought up.
  6. Aug 13 · 17:52
    First connection verified
    8 controllers active, /joint_states at 125 Hz, calibration checksum OK, external control accepted.
  7. Aug 13 · 19:32
    Driver daemonized
    Moved from a session-bound shell to systemd user unit ur10-driver (Restart=on-failure) — survives terminals and session ends.
  8. Aug 13 · evening
    Wedged controller diagnosed
    Dashboard alive but inert (play → “Failed to execute”, speed pinned at 0). Recovery: reboot controller from pendant, then remote power on + brake release over port 29999. Playbook written.
  9. Aug 14 · 12:20
    Reconnect handled, motion verified
    After re-cabling, the on-robot control script was dead (the expected failure mode). One call — resend_robot_program — re-armed it. Motion test: wrist_3 +2.86° and back, error_code=0, return within 0.0005 rad. PASSED.
  10. Aug 14 · 12:45
    “It's not moving” — visibility, not function
    The wrist_3 test rotates the bare flange <3° — physically real but nearly invisible. Re-run on wrist_1 (tilts the whole wrist block): encoders logged an 8.58° sweep across 1,293 samples with every other joint within 0.01°, return Δ 0.00016 rad. New demo-grade check: motion_test_visible.py.

05Runbook — the commands you'll reuse

Mirror of RUNBOOK.md in the repo. Every ros2 command needs source /opt/ros/jazzy/setup.bash first.

§1Is the robot reachable?

# ALWAYS bind the interface — plain ping false-positives via wifi
$ ping -I enp5s0 -c3 192.168.0.1
$ printf 'robotmode\nsafetymode\nprogramState\nquit\n' | nc -w5 192.168.0.1 29999
$ ~/ur10/ur-detect.sh   # full probe: ports, CB3-vs-eSeries, writes ur_type.txt

§2Driver service

# start (after PC reboot — transient unit, does not autostart)
$ systemd-run --user --unit=ur10-driver -p Restart=on-failure -p RestartSec=5 ~/ur10/ur-bringup.sh
$ systemctl --user status  ur10-driver
$ systemctl --user restart ur10-driver   # ALWAYS after rebooting the robot controller
$ journalctl --user -u ur10-driver -f

§3Health checklist after any (re)connect

$ ping -I enp5s0 -c2 192.168.0.1                                          # 1 link
$ ss -tn | grep ':50001'                                                  # 2 must show ESTAB
$ ros2 topic hz /joint_states                                             # 3 ~125 Hz
$ ros2 topic echo --once /io_and_status_controller/robot_program_running  # 4 data: true
$ ros2 topic echo --once /speed_scaling_state_broadcaster/speed_scaling   # 5 > 0

§4The #1 fix — robot reconnected / motion ignored

# re-arm the external-control script on the robot (causes no motion)
$ ros2 service call /io_and_status_controller/resend_robot_program std_srvs/srv/Trigger "{}"
# if controllers went inactive too:
$ ros2 service call /controller_manager/switch_controller controller_manager_msgs/srv/SwitchController \
    "{activate_controllers: [scaled_joint_trajectory_controller, friction_model_controller], strictness: 1}"

§5Wedged CB3 controller

# after rebooting the controller from the pendant:
$ printf 'power on\nquit\n'      | nc 192.168.0.1 29999   # wait ~6 s
$ printf 'brake release\nquit\n' | nc 192.168.0.1 29999   # ~15 s to RUNNING

§6Motion test

# VISIBLE test — wrist_1 tilts the whole wrist block ~8.6°
$ source /opt/ros/jazzy/setup.bash && python3 ~/ur10/motion_test_visible.py
# minimal test — wrist_3 = flange rotation, near-invisible without a tool
$ source /opt/ros/jazzy/setup.bash && python3 ~/ur10/motion_test.py   # ±0.05 rad, self-verifying
# speed slider must be nonzero:
$ ros2 service call /io_and_status_controller/set_speed_slider \
    ur_msgs/srv/SetSpeedSliderFraction "{speed_slider_fraction: 0.3}"

§7Controllers (ros2controlcli not installed)

$ ros2 service call /controller_manager/list_controllers controller_manager_msgs/srv/ListControllers "{}"

§8Live RViz view — arm mirrors physical motion

$ systemd-run --user --unit=ur10-rviz -E DISPLAY=:0 \
    bash -c 'source /opt/ros/jazzy/setup.bash && exec rviz2 -d $HOME/ur10/rviz/live_view.rviz'
$ systemctl --user stop ur10-rviz   # close it
# hand-guide: hold the teach button on the pendant's back — RViz follows live

§8bMoveIt — interactive planning (drag TCP, IK, planners)

$ systemd-run --user --unit=ur10-moveit -E DISPLAY=:0 ~/ur10/moveit/start_moveit.sh
# wait for the robot, then click "Reset" (bottom-left) ONCE → drag ball appears
# drag TCP ball → Plan → Execute · planners: Context tab (OMPL / Pilz / CHOMP)
# stock ur_moveit.launch.py is broken on Jazzy (type clash / missing IK) — use our starter
# SAFETY: planning scene is EMPTY — MoveIt does not know the table. Watch every Execute.

§9One-time / rare

# re-extract kinematics calibration
$ ros2 launch ur_calibration calibration_correction.launch.py \
    robot_ip:=192.168.0.1 target_filename:=$HOME/ur10/ur10_calibration.yaml
# reinstall driver stack (keeps the Isaac-repo pin)
$ sudo bash ~/ur10/install-ur-driver.sh
